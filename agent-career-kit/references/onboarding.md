# 首次使用与冷启动

本文件定义从“用户还不知道要提供什么”到“拿到首个可审阅产物”的最短路径。

## 目标

首次交互结束时，用户应该清楚：

1. 已经读取了哪些材料；
2. 目标 Offer 的岗位、城市、底线和时间；
3. 当前更适合哪个候选阶段和岗位方向；
4. 首版内容是什么；
5. 哪 1-3 个缺失事实最影响投递或面试；
6. 下一次确认后会推动哪个真实岗位。

不要把创建目录、填写 JSON、安装 LaTeX 或选择全部模块当成用户的第一步。

## 可启动输入

以下任意一种都足够：

- 已有简历或个人介绍；
- 一个目标 JD；
- 一个项目说明、仓库或论文；
- “我是校招生/有几年经验，想投 Agent 开发/算法”这样的自然语言描述。

材料不完整时先输出窄而真实的草稿，再指出缺口。只有姓名、目标方向和至少一段真实经历都缺失时，才需要先提问而不能给内容草稿。

## 材料导入

有文件时先运行：

```bash
python3 <skill-dir>/scripts/import_materials.py <workspace-dir> <file...> --kind resume|jd|project|interview|other
```

脚本保留原件，生成规范文本和 `source-materials/materials.json` 清单。Agent 读取提取文本并负责更新候选人档案，用户不编辑 JSON。

## 首轮输出格式

```markdown
# 首轮盘点

## 已读取
- 文件/链接：用途

## 当前定位
- 候选阶段：校招 / 有经验 / 资深 / 待确认
- 当前方向：Agent 开发 / Agent 算法 / 待确认
- 判断依据：具体材料

## 目标 Offer
- 岗位方向、城市、底线、目标日期；未知项标待确认

## 首版内容
可直接审阅的岗位标题、摘要和经历 bullet；不使用占位符伪装成完成稿。

## 最值得补充的事实
1. 问题，以及它会改变哪一段内容
2. 最多三项

## 下一步
用户确认后生成的具体产物，以及准备推进的真实岗位。
```

## 提问优先级

依次选择能最大幅度改变岗位定位或内容可信度的问题：

1. 候选人的实际贡献边界；
2. 项目解决的问题与可观察结果；
3. 关键技术决策或失败；
4. 目标岗位/候选阶段；
5. 时间、规模和常规背景字段。

不要问材料里已有的内容，不要一次问十几项表单字段，不要因为没有指标就拒绝给首版。

## 确认设计

- 实时访谈：一次一个问题。
- 草稿确认：一次展示原文、建议稿、证据和风险，最多汇总 3 个决策点。
- 用户可以“全部接受 / 接受其中几项 / 保持原文”。
- 只对 Agent 新写或实质改写的 bullet 记录 approval；原文导入不需要重复确认。
