# 内容分析

## 目标与受众

在原有两张浅色产品图基础上做增量更新。保留原图已经验证过的横向流程、4×2 卡片、图标、配色和信息层级，只替换与当前版本冲突的文案。

## 当前版本重点

- 任意一份简历、JD、项目或一句背景即可冷启动。
- 一份带来源候选人档案，按校招、有经验、资深分层判断证据。
- Agent 开发与 Agent 算法方向按需启用，可单方向也可双方向。
- JD 使用独立投递快照，不直接污染长期主档案。
- 用 `career-state.json`、转化漏斗和下一最佳动作驱动 Offer 求职驾驶舱。

## 视觉策略

- 原图布局、图标、配色、卡片尺寸、箭头关系全部保留。
- 仅替换必要文字，不重新设计结构。
- 中文必须完整、清晰，不添加提示词之外的文案。

## 两张图的分工

1. 流程图：保留 1→2→3、4A/4B 分支、5→6→7 和反馈回写；在原位置补充按需简历、JD 快照与 Offer 驾驶舱。
2. 介绍图：保留八张等大能力卡，只更新阶段化画像、按需简历、JD 投递包和 Offer 驾驶舱。

## 禁止出现

- 改变原图布局、图标、配色、卡片尺寸或箭头关系。
- 固定“双主简历”。
- “不按单个 JD 改写”这类会掩盖独立投递快照的旧表述。
- CSV、XLSX、Offer Tracker 旧架构。
- 虚构功能、求职结果或 Offer 保证。
